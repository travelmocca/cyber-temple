## 一、先解决许可和上线范围

目前没有确认原站整套程序、场景和素材的再分发/公开运营授权。改名字、汉化、换服务器不会自动使其成为自有原创。需取得适合实际用途的授权，或替换相应未获授权的程序和素材；商业用途要明确纳入核对。

音频目录有两份CC BY 4.0来源说明，其他素材仍需逐项核对。不得从某个声音或某个开源库的许可推定整站均可复用；原作者授权也应核对其包含的第三方素材范围。CC BY 4.0要求恰当署名、提供许可链接并注明修改，详见 [官方许可](https://creativecommons.org/licenses/by/4.0/)。音频来源记录位于 `site/audio/*.license.txt`，场景中的模型/艺术素材署名也应保留并核验。

若在中国内地公开提供此服务，应专门核实宗教信息服务要求。现有产品包含宗教文化介绍、真实寺院名称、礼佛、上香、诵念和供养入口，不能只按普通网站判断。工信部公布的 [《互联网宗教信息服务管理办法》](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2022/art_36c84b53178948ffba50dffaa7503cb1.html) 第6条规定相关宗教信息服务许可，第8条涉及服务名称，第17条限制网上组织宗教活动及部分宗教仪式传播，第19条禁止网上以宗教名义募捐。虚拟互动的具体适用和可运营范围需向所在地主管部门或专业人员核实，不能把“拿到许可”视为所有玩法都能上线。

境内网站的备案适用情况同时按实际运营主体、接入方式及业务核实，参考工信部 [《非经营性互联网信息服务备案管理办法》](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)。本仓库没有替你完成这些手续。

- 关于/说明、来源署名、支持或供养入口、联系渠道及可能的隐私说明：按自己实际服务配置。当前支付链接进入本地模拟页，不是可用的收款系统；不要把它作为真实交易反馈。若首版不做收款，可先移除相关入口。

## 三、服务器要运行Node和WebSocket

当前不是单纯上传静态HTML即可完整使用的站点。一个Node进程同时提供场景资源、`/temple-entry/`、房间HTTP接口及WebSocket。

本地验证：

```sh
npm ci
npm run check
npm run test:e2e
HOST=127.0.0.1 PORT=4191 npm start
```

使用自己的域名和HTTPS入口，把所有路径代理到此Node进程，保留原请求Host及WebSocket升级头。当前绝对资源路径以 `/` 开头，首版应部署到独立域名根路径；放到 `/temple/` 子路径需要额外改造。

例如，已有Nginx域名/TLS配置时，在 `http` 上下文配置：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}
```

在对应的HTTPS `server` 内配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:4191;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 300s;
}
```

升级头需要显式转发，见 [Nginx官方WebSocket说明](https://nginx.org/en/docs/http/websocket.html)。域名DNS、TLS证书、进程守护、主机防火墙、日志与监控需在目标环境配置；容器内监听地址通常需用 `HOST=0.0.0.0`，由宿主机和反向代理控制暴露范围。这里没有包含已验证的Docker/云平台配置。

生产安装可用 `npm ci --omit=dev` 后 `npm start`；格式、补丁生成与浏览器测试需要开发依赖，应在开发或CI环境安装完整依赖并完成。运行时至少包含 `package.json`、锁文件、`server/`、`locales/`、`site/`、`entry/` 和生产依赖；要在服务器执行资源校验，还需 `tools/`、`baseline/`、`patches/`。不要对外暴露整个仓库目录；当前Node仅提供 `site/` 与 `entry/` 静态资源。

## 四、公开运营前补齐运行能力

当前房间/活动状态是单进程内存数据，服务重启会清空；没有完成数据库持久化、多实例共享状态和真实收款。若需要长期保存进度、交易或账户，需先明确数据范围，再做存储、备份和恢复；不要直接开多个Node副本期待房间同步。

真实设备、Safari、网络断开、证书/代理后的WebSocket、容量及滥用防护需在目标部署环境验证。20个房间、每房50人的配置不等于已完成1000人并发压测。已测本地旅程可在外站请求被阻断时运行，但这不意味着包内所有外链、可选分支和原站品牌均已移除。

首次上线的技术验收应至少包含：自己域名的健康接口、两台独立设备进同一房间、不同寺院匾额、重连、音频与触控、重启后的状态行为和所有收款入口。业务/许可确认与这些技术检查分开记录。
