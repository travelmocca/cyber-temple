# 祈愿选寺入场验收

- 基线为汉化镜像934bda7，开发分支为codex/wish-temple-entry。
- 日期为2026-11-11。
- 功能覆盖八类祈愿、34个地区84座佛寺、每批五寺随机推荐、介绍与换批、统一场景入场及山门寺名。
- 后续活动、房间、身份及协议规则沿用基线。入场页以sessionStorage保存当前标签、批次、已见记录和最后选寺。

## 自动检查

- `npm run check` 包括格式检查、107项发布文件与9项补丁的完整性检查，以及34项单元／集成测试。
- 浏览器回归包含2项新入口用例及7项原场景用例。最终9项全部通过，失败0项，耗时约117秒。
- 桌面及390像素手机模拟已检查八类选择、五寺数量、去重、详情来源、横向溢出、名录失败重试及页面刷新恢复。
- 两个独立浏览器选择不同寺院进入同一原有房间17，实际Canvas文字绘制包含各自寺名。

## 两个独立审查

实现审查agent `entry_code_review` 已通过。其在隔离副本验证入口生成、两次汉化生成及补丁重建，关键输出逐字节一致，并验证HTTP路径穿越拒绝、0／3／5候选及缓存中停用条目处理。

验收审查agent `entry_acceptance_review` 已通过。其独立复现资源加载失败后恢复网络的重试，验证原批次、类别、已见记录与选寺均恢复，并目视确认场景山门清晰显示“金山寺”。

审查指出并已修复的问题包括会话重载丢失选择、停用条目过滤、缓存条目减少后补足五寺、卡片适配类型和逐类型来源字段。原浏览器测试已适配新入口及“再次停留”引起的页面重载。

本轮基线为选寺入场提交 `9e9d38a`。入口改为山门实景截图背景及底部悬浮面板，类别、五寺推荐和介绍在同一面板内切换。手机卡片横滑；选寺后保留背景及等待状态，真实场景就绪才淡出。未调整原场景发布包、房间或后续活动。

- `npm run check` 再次通过：34项测试、107项文件及9项补丁完整性检查，格式检查通过。
- 完整9项浏览器回归通过，耗时约135秒；随后对新增返回/横滑、WebGL初始化失败及模块失败重试运行3项定向浏览器测试，全部通过。
