# 项目运行说明

现有镜像已提升为仓库根目录，早期“云栖山寺”代码、素材、依赖和构建输出已删除。以下命令均在根目录执行，不再使用 `--prefix mirror`。历史研究证据目录 `RECON/mirror/` 保留原名，不是第二套应用。

## 安装、检查、启动

需要Node.js 22或更新版本；建议使用仍在维护的LTS版本。

```sh
npm ci
npm run check
npm start
```

默认监听 `127.0.0.1:4191`，可使用 `HOST`、`PORT` 环境变量覆盖。端口被占用时先检查现有服务，不终止无关进程；例如 `PORT=4193 npm start`。迁移前已经运行的进程不会自动更新路径，需要由其管理者重启。

```sh
curl http://127.0.0.1:4191/__mirror/health
npm run test:e2e
```

这是Node.js服务，不需要Vite构建。浏览器回归使用已安装的桌面Chrome和临时端口；移动端为触控模拟，不代表实体手机和Safari通过。`MIRROR_E2E_OUTPUT=test-results/custom npm run test:e2e` 可指定原场景回归证据目录，入口截图写入 `test-results/entry/`。

## 使用

先选择八类心愿之一，从五座推荐佛寺中查看介绍、换批并进入。所有寺院使用同一场景，所选寺院仅改变当前浏览器的山门匾额。

地图可选择12个地点，角色沿路径行走。拖动环视，滚轮缩放；WASD/方向键行走。数字键1礼拜、2念珠、3合掌、5木鱼。念珠画布获得焦点后可用方向键；木鱼支持手动和自动模式。

礼拜、上香和咖啡沿用原客户端约束。多人验证需使用两个独立浏览器上下文/隐私窗口并选择同一房间编号。同一浏览器多标签的渲染休息机制由原前端管理；四位常住僧不是服务器模拟访客。

供养入口为本地模拟，不会付款。生产部署前的处理事项见 [独立部署说明](self-hosting.md)。

## 目录与维护

- `site/`：对外提供的发布程序、模型、贴图、声音和字体。
- `entry/`：悬浮选寺入口、背景截图与84座佛寺配置，通过 `/temple-entry/` 提供。
- `server/`：自建HTTP/WebSocket及房间、活动服务。
- `baseline/`：107个原站文件的只读字节及来源/SHA-256清单。
- `patches/`：9项精确补丁，包含3项接入、4项汉化及2项选寺适配。
- `locales/`：中文词典及文本处理。
- `tests/`、`tools/`：回归测试、补丁生成和研究工具。

```sh
npm run format
npm run localize
npm run check
npm run test:e2e
```

`localize` 会接着重建选寺补丁。只有修订词典或相应补丁时才需运行；`npm run patch` 从只读基准重新应用已登记补丁。不要直接格式化发布包或修改只读基准。校验会拒绝资源缺失、篡改和未登记更改。详情见 [中文说明](zh-CN-localization.md)。

## 服务状态与限制

房间、访客、坐垫、上香、咖啡和施工状态在内存中，服务重启会清空。断线保留访客身份和位置最多30分钟，释放坐垫和队列。自建服务为单进程替代实现，默认20房间、每房50人；此配置不是生产容量承诺。多地区、多实例共享状态、长期持久化和原站部分活动未实现。

HTTP及WebSocket内部仍保留 `/__mirror/health`、`/__mirror/payment` 等协议路径；本轮只搬目录，不修改协议和玩法。完整差异见 [镜像交付历史验收](mirror-acceptance.md) 和 [后续选寺验收](wish-entry-acceptance.md)。

历史记录见 `RECON/`。早期原型的已跟踪文件可从Git提交 `1671535` 及更早历史恢复，不在当前工作目录继续维护。
