# 山寺完整体验重制计划

目标是独立重建冻结版本的公开访客体验，并用可复查的原站和本地证据逐项验收。旧版继续作为功能原型。每一阶段先取证，再实现并对照。证据缺失或效果差异明显时，保留未通过状态。

## 1. 冻结原站并建立可重复对照

- [ ] 记录日期、公开入口、构建包哈希、浏览器、视口、画质、时间模式、镜头、访客位置与输入。用户提供的山门图作为首个视觉参考。
- [ ] 保存导航前启动的网络记录、浏览器画面及关键 WebGL 帧记录。识别哪些来自应用代码、哪些由通用渲染库提供。
- [ ] 扩展 `RECON/baseline/experience-matrix.md`。每行记录原站证据、触发条件、输入与输出、替换项、本地证据和验收结论。先确定公开可达范围，再冻结。
- [ ] 将原站资源路径、内容哈希、用途、授权和替换方案写入资产清单。浏览器可见只说明可研究。发布版本使用自制或明确许可的资产。

通过条件为参考路线能重跑，首关包含固定机位、移动镜头和至少一个可解释的渲染效果。

## 2. 通过山门样板关

- [ ] 在 `RECON/runtime/` 为相机、山门和石路布局、池水、地灯、角色与秋林分别建立证据。记录代码位置、运行观测，以及仍无法确认的部分。
- [ ] 在 `src/courtyard.mjs` 独立实现池水的环境反射，保存可验证的环境采样结果。对照固定机位和改变视角后的高光方向与倒影。
- [ ] 用原站相机参数和地标坐标校准 `src/world.mjs` 的透视、比例与路线。将有证据的参数和美术拟合值分开。
- [ ] 验证角色轮廓、服装、山门木纹、石路接缝、地灯暖光、地面接触阴影和树叶密度。资产制作先做可并排看的近景样片，再扩展至全场。
- [ ] 对照 1920 × 902 入口固定帧、近景帧和从山门进入法堂的同路线录屏。记录明显偏差及对应责任资产。关键物体轮廓、构图、明暗层次、移动视野和听感全部通过后进入下一关。

## 3. 重建完整世界与单人体验

- [ ] 按原站公开地图逐区核对场景连通、地标位置、通道宽度、高差、碰撞、背景、遮挡和音区。发现的新公开区域回填矩阵。
- [ ] 记录桌面和触屏上点击行走、相机、缩放、落座、合掌、礼拜、木鱼、念珠、诵念和声音设置。逐个比较起势、停顿、结束、可中断条件及界面反馈。
- [ ] 对茶舍、祈愿、共香、早晚课、回访、退出、加载与失败恢复建立场景和证据。只用可验证的行为定义等价标准。
- [ ] 每区交付固定帧、路线录像和可重复交互用例。实现与原站的视觉、动线或反馈差异显著时，该条保持未通过。

## 4. 重建多人体验与活动

- [ ] 两个独立访客从导航前开始分别记录，核对房间、相互可见、动作事件、座位归属、移动插值、切房、断线重连和状态清理。
- [ ] 用同样步骤验证两端看到的反馈。对席位竞争、满房与掉线引入可重复的本地条件并复测。服务端内部实现可独立，只按已记录的公开体验验收。
- [ ] 对定时活动录制触发前、进行中和结束后。供养保留可体验的流程并走本地测试交易。受时段限制的原站证据保留待验。

## 5. 整站交付验收

- [ ] 对每条公开体验执行同机位、同路线、同输入或同多人条件对照。使用分辨率、相机、角色姿态、光照时段明确的基线，单人和双人录像分别保存。
- [ ] 阻断原站和其 CDN 后跑生产构建。运行 `npm test`、`npm run test:e2e`，另测首次加载、帧率与桌面 Chrome、Safari、iOS Safari、Android Chrome 的核心旅程。模拟结果和真机结果分开。
- [ ] 更新 `docs/acceptance.md`。公开路线、交互、场景、活动与设备矩阵均通过后标记完整。静帧通过、可运行原型和本地测试通过只记各自的验收结论。
