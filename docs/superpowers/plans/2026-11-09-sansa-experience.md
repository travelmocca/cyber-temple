# 赛博寺庙完整体验复刻计划

**目标**　把山寺原站已观察到的公开访客体验复刻为可独立运行的项目。用原站与本地的同条件对照验收，覆盖首次进入、游览、静修、多人共处、回访和异常恢复。

**范围假设**　以取证时的公开 Web 版本为基线，覆盖 PC 和手机浏览器。核心流程、反馈、交互时序与空间氛围对齐，品牌及素材用自有或许可明确的版本。原站若有真实支付或赞助，验收到入口及确认流程，交易用本地测试流程。限时活动通过观察记录、公开说明和可重复的时钟测试取证。无法验证的体验保留为未验收项。

**架构**　客户端负责 Three.js 场景、操作、音频和 UI。独立服务负责访客、房间和 WebSocket 状态同步。场景、资源与活动由本地清单驱动，测试可注入随机种子和时钟。建议使用 TypeScript、Vite、Node.js 和 Playwright，具体版本在实现前锁定。

## 1. 冻结原站基线

- [ ] 从新访客导航前开始采集。用 REA 记录页面、打包脚本和 CDP 证据，用浏览器记录公开流程的截图、视频、网络时序和音频触发点。
- [ ] 用桌面和手机分别走一遍访客旅程。按入口、空间、操作、界面、设置、活动、回访和错误状态盘点。对原站确实出现的功能保留证据路径，对只出现在 bundle 的功能标记待复核。
- [ ] 两个独立访客进入同一房间，记录出现、移动、姿态、席位交互、离开、断线与重连。另测跨房间可见性、满房或切房时的公开反馈。只记录测试访客相关的行为证据。
- [ ] 将结果写入 `RECON/baseline/experience-matrix.md`。每条记录包含编号、前置条件、操作、预期、来源、桌面/手机适用性和状态。原站变更时保留冻结基线，单独记录差异。
- [ ] 输出 `RECON/baseline/asset-inventory.md`，标注每项模型、贴图、音频和字体的用途、授权状态、替换资产及视觉或听感对照项。

**通过标准**　所有已发现公开入口均已分类。主链路有完整原站记录，房间和同步有双访客证据。任何观测缺口均有复核路径。

## 2. 重建单人体验

- [ ] 在 `src/world/` 重建场景图、入口、路径、落座点、灯光、镜头和碰撞。用固定相机检查场景比例、遮挡、视线和空间连通。
- [ ] 在 `src/avatar/` 实现访客控制和动作状态。先测试落座、起身、礼拜和移动互斥，再逐个实现并与原站录像比对动作长度和反馈。
- [ ] 在 `src/ritual/`、`src/audio/` 实现取证确认的念珠、仪式和声音交互。验证计数边界、重置、音频开关、首次播放授权及前后台切换。
- [ ] 在 `src/ui/` 实现进入、加载、菜单、提示、设置和手机触控。验证键鼠、触控、横竖屏、首次访问与回访。

**通过标准**　新访客可独立走完原站对应路径。矩阵中的单人条目都有本地截图、录屏或自动化断言。

## 3. 重建多人体验

- [ ] 在 `server/` 实现访客会话、房间、初始快照与状态更新。按照取证到的外部行为决定分房、切房、人数与席位规则。
- [ ] 在 `src/realtime/` 实现连接、插值、动作同步、离开与重连。用明确的服务端状态和清理规则处理抢座、重复消息、刷新和临时断网。
- [ ] 在 `tests/e2e/multiplayer.spec.ts` 用两个独立浏览器上下文回归同房可见、跨房隔离、动作同步、竞争、断线清理与恢复。用独立测试服务构造满房和延迟场景。

**通过标准**　两位访客可同时游览和静修。双方视角的最终位置、姿态、席位和在线状态一致，重连后恢复到可继续操作的状态。

## 4. 补齐完整体验并验收

- [ ] 逐条实现矩阵中的剩余公开体验，覆盖场景切换、活动、辅助入口、移动端、低性能和错误恢复。对动态时间和稀有状态使用可控时钟与本地服务数据复测。
- [ ] 固定相机、视口、访客初始状态和动作脚本，对照关键截图与录屏。分别核对空间构图、移动节奏、动作、UI 反馈和音频。品牌与合法替换素材的差异单独列明。
- [ ] 从干净环境按启动说明安装、构建并启动。验收时拦截原站和原站 CDN 域名，重跑首次进入、仪式、房间和重连，验证关键体验可独立运行。
- [ ] 在桌面 Chrome、Safari、iOS Safari 和 Android Chrome 验证主要路径。Playwright WebKit 与手机模拟结果分别记录，真机未跑的条目保留为未验收。
- [ ] 产出 `docs/acceptance.md`，逐条链接原站证据、本地证据和差异结论，附启动方式与测试结果。

**完成条件**　矩阵中适用的条目全部通过，原站无法复核、真机未验证、体验降级等事项有独立结论。任何仍阻碍完整体验的条目继续修复和复测，直到通过。阶段性可运行版本仅用于验证，交付以全量验收为准。
