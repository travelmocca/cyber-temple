# 自建镜像代码的等行为重构

目标：格式化 `mirror/` 自建代码，按职责拆分服务端，保持当前功能、消息字段、事件顺序、时间边界和已知限制一致。

边界：`mirror/site/`、`mirror/baseline/`、补丁内容及旧原型不参与重构。保留现有启动命令、导出接口及端口。咖啡账户等离线状态残留属于现有行为，本次不修复。

## 实施步骤

1. 将自建代码、配置和文档保存到 `.snapshots/pre-maintainability-refactor-2026-11-11/`，记录 SHA-256；运行原有测试。
2. 在修改运行时代码前，捕获确定性协议轨迹与状态基线，覆盖会话、请求去重、上香、施工、咖啡及时间边界。固定随机 ID 和时钟；轨迹必须来自旧实现。
3. 拆分 HTTP 处理、WebSocket 连接、协议分发、活动职责；保留 `index.mjs`、`presence.mjs`、`activities.mjs` 的公开接口。避免改写业务条件。
4. 固定 Prettier 版本，增加显式限定自建文件的格式化与检查命令，格式化服务、工具及测试。
5. 运行旧测试、完整轨迹比对、HTTP/WebSocket 回归、浏览器测试、格式检查和资源校验。验证比较器能检出刻意扰动；保存证据到 `RECON/refactor-2026-11-11/`。
6. 更新结构说明及维护入口，重启本项目预览并检查健康状态。

## 验收依据

- 重构前后同一输入的完整有序消息及状态快照相同。
- 原有 25 项测试和 6 项浏览器测试通过。
- 原站运行资源和只读基线的 SHA-256 保持不变，原有三处补丁校验通过。
- `npm run format:check` 通过；历史验收证据不覆盖。

测试只能验证所覆盖的输入；不将有限测试表述为对所有可能输入的形式化证明。

## 执行结果

六步已完成。最终全新安装、格式和资源校验通过；27 项单元/集成测试及 6 项 Chrome 界面回归通过。478 步/711 条协议消息、35 种 HTTP 请求与旧实现一致。验收记录：`RECON/refactor-2026-11-11/report.md`；模块职责：`mirror/README.md`。
