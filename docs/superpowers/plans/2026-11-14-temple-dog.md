# 庭院柴犬实施计划

**目标：** 在已有寺庙庭院加入一只具有真实骨骼动画的柴犬，随机散步和停留。

**已确认范围：** 用户允许将未开放下载的 LenikArt 小狗替换为有明确许可的动画小狗。采用 Quaternius Ultimate Animated Animal Pack 的 ShibaInu，作者页面明确标为 CC0。单机装饰 NPC，不新增喂食、跟随或多人同步。

**架构：** 新资源和控制器放在 `entry/`，由已有 `/temple-entry/` 静态入口提供；给发布包增加可重建、版本校验的场景创建、更新和销毁补丁。直接复用包内 Three.js 类和 GLTFLoader，不再下载第二份 Three.js。冻结 `baseline/` 保持不变。

**行为：** 在山门内中央庭院 x=-5.5..5.5、z=31..42 内挑选随机目标；检查整段路线及身体余量，复用游戏碰撞函数；按实际地面高度贴地。待机 2..5 秒后，以约 0.72 单位/秒散步，转身后行走并交叉淡化待机/行走动画。高度约 0.65 单位。素材加载失败仅缺少小狗，不阻塞入寺；销毁时取消下载并释放动画、模型和材质。

**文件与步骤：**

- [x] `tests/dog.test.mjs`：先验证随机路径不穿障碍、不越界，阻塞与异常帧时间下保持有效状态；运行并确认模块缺失失败。
- [x] `entry/dog.mjs`：实现受约束的巡游、独立资源加载、尺寸适配、动画和释放。
- [x] `entry/dog/`：保存完整 GLB 和来源记录，固定副本提交、SHA-256、原作者和 CC0 链接。
- [x] `tools/generate-dog.mjs`：以五处精确编辑登记一项补丁并更新游戏模块版本；`tools/generate-entry.mjs` 及本地化生成链重新接上生成器。
- [x] `tests/browser/dog.test.mjs`：桌面和移动窗口真实加载，验证行走和待机、朝向、尺寸、贴地、原有猫仍存在；模拟模型失败验证原场景可进入；验证销毁和加载中销毁。
- [x] `npm run check` 和相关浏览器回归；独立两位子 agent 审查代码与验收，修复实际问题后复核。

**验收与交付：** 保存真实场景截图；记录新增载荷和测试结果。未经本轮用户要求不提交、不推送、不部署；保留用户现有未跟踪目录。

## 完成记录

- `npm run check`：47/47 通过，含 5 项小狗单元测试；107 个冻结文件、13 项补丁完整性通过。
- `MIRROR_E2E_OUTPUT=test-results/dog/regression npm run test:e2e`：14/14 通过，包括入场/缓存、中文界面、原有活动、多人房间/断线恢复、触屏操作、匿名统计和小狗的两项浏览器测试。日志：`test-results/dog/e2e.log`。
- 桌面、手机窗口分别模拟 180 秒巡游，出现真实待机与行走状态；46 根骨骼中有 29 根改变姿态；实测身体最大水平半径约 0.449，小于最终碰撞半径 0.55。模型加载 404 和下载中销毁不阻塞入寺，模型和阴影资源只释放一次。
- 两位独立子 agent（`dog_code_review`、`dog_asset_review`）最终复核通过。代码审查发现初始半径 0.35 不能覆盖头尾，已先增加失败回归，再修为 0.55；验收脚本也修正了首根骨骼恒定及行走姿态高度变化导致的误报。
- 分别调用 `generateLocalization()`、`generateEntry()` 重建，确认补丁注册、HTML、游戏 JS、入口 JS 和 CSS 的 SHA-256 与重建前完全相同。
- 新增模型 540,592 字节（约 528 KiB），控制器 7,965 字节；无外部贴图或第二份 Three.js。模型按内容文件名长期缓存，本地 HTTP 已确认正确 MIME/200/immutable。
- 截图 `test-results/dog/desktop.png`、`mobile.png` 是真实游戏场景调整相机后的近景，不是玩家默认镜头。
- 边界：移动验证使用 Chrome 手机窗口模拟，未覆盖实体手机；原猫检查验证实例保留，未重新逐项验收所有猫交互。未部署到公网。
