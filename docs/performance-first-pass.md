# 第一轮性能优化效果

日期：2026-11-11。基线提交 `a34eb9d`；优化范围为字体、入口背景和HTTP缓存，未调整模型、场景、房间或活动规则。当前交付为本地验证结果，未执行公网部署。

## 实际效果

下表采用同一机器Chrome、浏览器冷/暖缓存、模拟10 Mbps下载和80 ms延迟。本地HTTP未启用Brotli或CDN；桌面为1280×800、3次的中位数。MB/KB均采用十进制。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | --- |
| 桌面首屏资源总传输量（含图标） | 808,854 B | 405,654 B | 减少49.8% |
| 桌面选寺界面可操作时间 | 0.853秒 | 0.660秒 | 减少22.6% |
| 首次入寺，含后续固定观察资源集的总流量 | 20.98 MB | 18.60 MB | 减少11.4% |
| 首次点击进入至场景就绪 | 8.67秒 | 8.80秒 | 基本持平，未测得改善 |
| 同浏览器回访，含后续观察资源集的总流量 | 20.98 MB | 7.47 KB | 减少约99.96% |
| 回访点击进入至场景就绪 | 8.57秒 | 3.51秒 | 减少59.1% |

手机390×844触控模拟为1个样本，不能当作稳定的真机中位数：首屏总传输量从808,854 B降至357,661 B（减少55.8%）；完整观察流量从20.98 MB降至18.55 MB；首次入场9.22→8.79秒，回访9.17→3.51秒。

首次入场仍需下载/解码模型、准备渲染，因此首屏和流量减少没有带来同等幅度的首次入寺提速。回访仍有约3.5秒场景初始化，缓存不能消除这部分工作。

线上站点在优化前已经使用Cloudflare、Brotli，部分静态资源声明4小时缓存。上面的回访对比对象是仓库原Node服务，不能把99.96%或59.1%直接当成既有公网部署的收益。部署后还需检查CDN是否覆盖源站缓存头，并在目标地区/真实手机复测。

## 已实现

1. 保留原基础字体和全部原始字体文件；运行CSS停用1,998,920 B的扩展字体。入口不再预载142,748 B的基础字体，进入场景后按CSS需要加载。中文仍使用现有系统字体回退。
2. 桌面背景由361,015 B JPG生成1600×900、100,032 B WebP，减少72.3%。手机竖屏使用中心裁切810×1080、52,040 B WebP，减少85.6%；媒体条件限定竖屏比例以保持原有构图。原始JPG保留。
3. 静态资源提供SHA-256 ETag和304；HEAD及音频Range保留，过期If-Range返回完整200。HTML及寺院名录（含路径别名）保持no-cache验证更新；JSON状态接口沿用no-store。
4. 内容摘要匹配的版本查询/文件名与冻结 `/v/<版本>/` 资源使用一年immutable缓存。入口JS/CSS及大游戏JS/CSS使用内容版本；生成器校验依赖摘要，修改入口源文件却未更新版本时检查会失败。
5. 3项性能补丁独立登记。原Vite预载器做了最小适配，以正确识别带查询参数的CSS。`localize`、`entry:patch`、性能生成器及`patch`均可重复重建相同字节。

原始107个文件的SHA-256全部保持；运行副本102个文件与原版相同，5个文本目标经12项补丁修改。原稿、字体、模型与声音保留，仓库体积基本不变。

## 测量与复现

基线运行来自优化前代码的独立快照；优化服务采用相同硬件和浏览器。首次访问使用全新浏览器上下文，回访保留同一上下文的HTTP缓存，清除选寺进度以保持入口步骤一致。计时分别记录选寺可用和点击入场至浮层隐藏。

首屏流量单独等待网络静默后统计，包含不会阻塞可用性的favicon。全流程流量等待场景延迟加载的松树资源完成并再次网络静默，避免漏算后台资源；首屏可用时和场景就绪时的字节快照不能解释为全部资源已经完成下载。桌面完整流程和首屏流量各3轮；手机各1轮，无其他自动化浏览器并行采样。

```sh
PERF_URL=http://127.0.0.1:4193 PERF_OUTPUT=test-results/performance/current.json node tools/measure-entry-performance.mjs
PERF_ENTRY_ONLY=1 PERF_URL=http://127.0.0.1:4193 PERF_OUTPUT=test-results/performance/current-entry.json node tools/measure-entry-performance.mjs
PERF_MOBILE=1 PERF_RUNS=1 PERF_URL=http://127.0.0.1:4193 PERF_OUTPUT=test-results/performance/current-mobile.json node tools/measure-entry-performance.mjs
```

原始样本和汇总位于 `test-results/performance/`。本次制作背景命令为 `cwebp -q 72 -resize 1600 900` 与 `cwebp -q 72 -crop 555 0 810 1080`，输入为保留JPG；输出采用内容摘要文件名。
